# HTTPS 不同版本的区别

## 概述

HTTPS 通过 TLS/SSL 协议提供加密通信，不同版本在安全性、性能和兼容性方面存在显著差异。

## TLS 版本对比

### TLS 1.0 (1999 年)

- **安全性**: 低
- **已知漏洞**: BEAST、CRIME、Lucky 13 攻击
- **状态**: 已弃用

### TLS 1.1 (2006 年)

- **安全性**: 中等
- **改进**: 修复了 BEAST 攻击漏洞
- **状态**: 已弃用

### TLS 1.2 (2008 年)

- **安全性**: 高
- **特性**: 支持 AEAD 加密、强哈希算法、椭圆曲线密码学
- **状态**: 广泛使用，安全可靠

### TLS 1.3 (2018 年)

- **安全性**: 最高
- **特性**: 零往返时间、强制前向安全性、更快握手
- **状态**: 最新标准，强烈推荐

## 性能对比

| 版本    | 握手延迟 | 安全性 | 兼容性 | 推荐程度 |
| ------- | -------- | ------ | ------ | -------- |
| TLS 1.0 | 高       | 低     | 高     | ❌       |
| TLS 1.1 | 高       | 中等   | 高     | ❌       |
| TLS 1.2 | 中等     | 高     | 高     | ✅       |
| TLS 1.3 | 低       | 最高   | 中等   | ✅       |

## 配置建议

### 服务器配置

```nginx
ssl_protocols TLSv1.2 TLSv1.3;
ssl_ciphers ECDHE-RSA-AES256-GCM-SHA512:ECDHE-RSA-AES128-GCM-SHA256;
```

### 最佳实践

- 禁用 TLS 1.0 和 1.1
- 优先使用 TLS 1.3
- 配置强加密套件
- 定期更新证书

## 总结

- **TLS 1.3**: 最新、最安全、性能最好
- **TLS 1.2**: 当前广泛使用的安全版本
- **TLS 1.0/1.1**: 已过时，存在安全风险
- 建议新部署使用 TLS 1.3，逐步淘汰旧版本
